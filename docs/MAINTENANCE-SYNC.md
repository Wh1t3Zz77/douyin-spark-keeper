# 2026-10-14 维护同步

## 2026-10-20 压力恢复修复

压力保护曾将尚未发送的项记成跳过并直接终止，即使随后压力恢复也不再执行。现在将这些项保留为失败，只对明确未提交的消息创建非空重试，仍最多共三次尝试，仍等待五分钟与压力恢复；不确定结果继续人工核对。部分消息已提交时仅重试其余项，重试成功结算父链，全部已经提交的批次按成功收尾。

worker 的 RAM 及内存加交换空间上限均调整为 1024 MiB，继续禁用交换，为短时峰值提供 124 MiB 余量。中等等待 full avg10 达 10% 连续 20 秒才暂停，避免下降中的短峰值误停；full 达 30% 或可用内存低于 128 MiB 时仍连续 6 秒停止。保留 init、单浏览器、容器回收和 1200 秒超时。压力日志增加主机可用内存和 PSI，便于区分资源紧张与阈值触发。下文 2026-10-16 的 900 MiB 设置及三次采样策略为当时历史配置。

## 2026-10-16 追加修复

修复页面加载异常被误记为“跳过”并创建空重试、从而漏掉失败通知的问题。未发送项进入有效重试；最多 3 次尝试后通知。已提交或结果不确定的项不会自动重复发送。超时、进程中断和登录失效收尾同步结算重试父链。

会话查找改为每轮一次批量 DOM 身份读取，并设置 45 秒整体查找预算，替代逐个虚拟列表元素等待。仍在点击前及发送前核验稳定身份，不回退按昵称匹配。导航以提交为节点，再等待会话列表就绪；输入框点击最多等待 5 秒，整次任务仍保留 1200 秒硬上限。

新增浏览器阶段耗时和邮件重试日志，均不包含真实地址、联系人身份、消息正文或凭据。历史误记状态需由维护者在备份后核对修正，不随启动自动改历史、不自动重发旧消息或邮件。

前端仅有一个客户端页面，API 由独立后端提供，因此改为 `output: 'export'`，构建产物位于 `dist/client`。Docker 前端由 Caddy 提供静态文件，不再常驻 Node。构建仍需要 Node；`npm start` 保留为本地查看方式。作者站点由现有 Nginx 提供静态文件，并保留旧哈希资源供已打开的页面继续使用。

小内存主机出现严重回收等待时，浏览器自己的 5 秒超时可能很晚才返回。worker 每 2 秒检查一次内存 PSI；full avg10 达到 10% 或可用内存低于 128 MiB，连续 3 次则停止当前浏览器并结算，等待压力恢复才开始下一项。没有把高压失败自动变成无限重试，也不会重复提交不确定消息。Linux PSI 不可用的平台保留原有硬超时。

Compose 的 `SPARK_RECYCLE_AFTER_RUN` 默认为 `1`：每批发送收尾后退出 worker，由 `unless-stopped` 重启，借助 init/PID 命名空间结束整个浏览器进程树。使用此选项时必须保留 Compose 的重启策略；直接运行 Python 时默认不启用，避免意外退出后无人重启。worker 的内存及内存加交换空间仍均为 900 MiB，总任务上限仍为 1200 秒。发送阶段过滤图片和视频，登录扫码与好友同步不套用该过滤。

本次将作者站点近期已经上线的身份、同步、总览、失败通知和执行保护修复同步到社区仓库，保留自托管版的配置与使用方式。作者站点公安备案页脚于 2026-10-13 上线。

## 好友与历史数据

昵称、备注和抖音号用于显示和搜索，不能代替稳定收件身份。计划和运行明细记录 Contact 本地 ID 与稳定身份快照；同步读取聊天页及被动资料响应，不为好友批量打开主页，发送前和打开会话后均核验身份。

启动时迁移身份相关字段和计划好友唯一约束。请先备份数据卷；遇到“缺少稳定好友标识”时，重新同步、从明确的好友记录重新选择并保存计划。系统不会仅凭旧昵称自动猜测收件对象。最近列表保留已选好友和计划引用，历史记录仍保存在数据库用于绑定与审计。

总览只在同一计划内对可唯一对应的旧名称记录做兼容，显式不同 ID 不按同名匹配。当天已提交发送不会被后续失败记录覆盖。

## 通知

用户继续通过自己的通知设置选择是否收邮件。可配置 `TASK_FAILURE_ADMIN_EMAIL` 让部署管理员独立接收终止失败通知；留空则关闭管理通知，与 `ADMIN_EMAIL` 的登录身份设置互不影响。

首次执行加两次重试，共最多 3 次尝试，重试中不发送失败邮件。登录失效、安全验证、身份缺失和不确定结果等停止执行后通知。按运行失败事件去重；同一收件邮箱不发两份。不同失败计划可以分别通知，不启用账号级每日失败合并或全部计划结束后的失败汇总。

## 执行与部署

worker 使用独立任务进程，1200 秒整次任务硬超时，退出时清理进程组。不确定发送结果不会自动重试。Compose 保留 init，worker 内存及内存加交换空间总额均为 1024 MiB；API 为 300 MiB，前端为 260 MiB。

小内存服务器应先在其他机器构建，或使用 `docker compose build api`、`docker compose build frontend` 分别串行构建；不要同时构建多个服务。升级前确认没有正常任务正在执行，备份数据库并保留回滚镜像。回滚代码时不要恢复旧数据库覆盖新执行记录。

## 备案页脚

在 `.env` 中填写自己的完整备案号：

```dotenv
NEXT_PUBLIC_ICP_NUMBER=你的完整ICP备案号
NEXT_PUBLIC_PUBLIC_SECURITY_NUMBER=你的完整公安备案号
```

公安号应含 14 位备案数字。前端自动生成 `https://beian.mps.gov.cn/#/query/webSearch?code=备案数字`，原比例图标位于编号前。ICP 号链接到 `https://beian.miit.gov.cn/`。默认留空，不给未备案或他人部署的域名标注作者站点编号。

修改后重新构建前端，配置会写入公开的页面资源。作者站点使用的编号是“浙ICP备2026076430号-1”和“浙公网安备33010602015002号”，仅用于其已批准的域名。
